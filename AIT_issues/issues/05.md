## 设计

**模型属性（实验控制变量，统一放在一处）**

| 属性 | 含义 | 取值 |
|---|---|---|
| Prop_Policy | 控制方式 | 1 = 脉动（Pulse），2 = 完工驱动（Flow） |
| Prop_NumPlanes | 批量 | 75 / 100 |
| Prop_NumSA103 | 其中 SA103 的数量 | 0 / 25 |
| Prop_PulseDays | 脉动周期（日历日） | 4 / 3.5 |
| Prop_CellCap | 工位容量 | 1 / 2 |
| Prop_Buffer | 工位之间的缓冲位 | 0 / 1 / ∞ |
| Prop_LaborPolicy | 人力方案 | 见 #11 |
| Prop_Shift | 班次方案 | 见 #13 |
| Prop_NumLines | 线数 | 1 / 2 |
| Prop_Deterministic | 确定性开关（验证用） | True / False |

**飞机实体 `Ent_Plane`**，状态：PlaneID、PlaneType（1/2/3）、**CurLoc（当前位置：0 = 线外投放池，1–5 = 工位，6 = 线外补工区）**、EnterLineTime、各工位的进入和离开时间，以及 OpenWO（脉动线使用）。CurLoc 在进入每个物理位置时更新，**只用于定位和统计，不参与工序取数**；工序取数只看 Tbl_Tasks.OwnerCell（见 #3）。用附加标签显示 `PlaneID-型号`；按原则 8.1，标签使用本地状态。

**投放逻辑 `Prc_飞机创建初始化`**：`MySource1` 按 `Prop_NumPlanes` 创建飞机，放入线外投放池，不计入 WIP。型号按不放回抽样确定：剩余数量 R1、R2、R3，令 P(型号 i) = Ri/ΣR，抽中后对应数量减 1。使用随机流 101，保证每次重复都严格是 45/30（/25）架。之后经 `TN_Release` 按 `Prop_Policy` 和 `Prop_NumLines` 分流到对应生产线（原则 6）。正式包已保存 Flow 路由表达式并包含 5 个验证场景的实验结果；见 `docs/issue-5-validation.md` 的最终包复核记录。

**机械师**（按 #4 验证结论）：
- 使用 Worker 对象表达机械师，每条线、每个工位配置一个 Worker 群体：`Wkr_L{1|2}_C{1..5}`，每个群体 8 名 Worker。任务资源需求按 `Mechanics` 取得相应数量的 Worker；已用原生 ResourceUsage 日志验证一项 `Mechanics=3` 的任务同时占用 `Wkr_L1_C1[1]`、`[2]`、`[3]`。
- 两条线共 10 个 Worker 群体、80 名 Worker。设施视图只放置群体对象，不创建 80 个单人 Resource 或配套 ObjectList，以避免布局过密。
- Worker 群体的 `Initial Work Schedule` 引用模型属性 `Wkr_InitialWorkSchedule`，由实验场景在运行初始化时选择周计划。`Prop_Shift` 是班次方案编号，单独修改它不会自动动态切换运行中的 Worker 日程。

**工作日程（Data → Schedules）**：
- 日模式 Day_2Shift、Day_3Shift
- 周计划 Sch_S0（两班，周一至周五）、Sch_S1（两班，七天）、Sch_S2（三班，周一至周五）、Sch_S3（三班，七天）
- 四种工作日程由 `Wkr_InitialWorkSchedule` 属性选择，实验 Scenario 分别绑定 `Sch_S0` 至 `Sch_S3`。`Prop_Shift` 与 Worker 日程不是自动联动关系。
- 周末零容量检查适用于 S0/S2；S1/S3 按设计在周末继续排班，不能要求周末整段为零。
