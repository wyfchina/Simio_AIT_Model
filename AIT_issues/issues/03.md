## 目标
建立**单一工序总表 `Tbl_Tasks`**，把 5 个工位的 83 道工序全部放进一张表。这样任意位置的飞机或工作订单都能用 `OwnerCell + PlaneType` 查到工序，traveled work 跨工位执行时不需要切换表。同时建立关联表，并接入 Excel，保证数据只有一个来源。

## 关键概念：责任工位 ≠ 飞机位置
- **`OwnerCell`（责任工位，表字段）**：这道工序归哪个工位的班组负责，也就是由谁来做。它是工序的固有属性，永远不变。
- **`CurLoc`（当前位置，飞机状态，见 #5）**：飞机此刻停在哪个工位。它随移动而变化。
- **完工驱动线（#6）**：飞机做完才走，所以执行工序时 `CurLoc == OwnerCell`，两者恒等。
- **脉动线（#9）**：飞机到 4 天就走，traveled 工序执行时 `CurLoc > OwnerCell`，两者可以不同。

**陷阱**：不能把 OwnerCell 当成“飞机必须停在这里才能做”。如果在飞机所在的物理工位 Server 上直接跑 Task Sequence，Server 要等全部任务完成才放行，飞机在 4 天时就走不了；强行移走的话，剩余任务会丢失。所以脉动线必须把位置和作业解耦（见 #9）。

## 表结构

**Tbl_Tasks（83 行，主键 TaskID）**

| 字段 | 类型 | 说明 |
|---|---|---|
| TaskID | String，Key | `C<工位>-<行号>`，例如 C2-07，顺序与 Excel 原表一致 |
| OwnerCell | Integer，Foreign Key → Tbl_Cells.CellID | 责任工位 1–5：由该工位的班组执行。**不表示飞机位置** |
| Seq | Integer | 工位内的优先序号（见 A2），直接用作 Task Sequence 的 Sequence Number |
| TaskName | String | 英文原名 |
| Mechanics | Integer | 同时占用的机械师人数 |
| T101_Min / T101_Mode / T101_Max | Real（小时） | SA101/SA103 的三角分布参数 |
| T102_Min / T102_Mode / T102_Max | Real（小时） | SA102 的三角分布参数 |
| T101_Mean / T102_Mean | Real（小时） | (Min+Mode+Max)/3，只用于确定性验证（#8） |

**Tbl_Cells（5 行，主键 CellID）**：工位主数据，包括 CellID、CellName、MechList（当前人力策略下该工位班组可用的 ObjectList 名称，由 #11 切换）。Tbl_Tasks.OwnerCell 引用这里的 CellID。

**Tbl_Stations（按线×工位，主键 StationID = 线号×10 + 工位号）**：Line、CellID（FK，物理位置）、ServerRef（物理工位）、MechList（该线该工位的机械师列表）。双线方案（#12）用到它。

**作业时长表达式（写在 Task 的 Processing Time 上，并在字段 Description 中用中文说明）：**
```
Math.If(ModelEntity.PlaneType == 2,
        Random.Triangular(Tbl_Tasks.T102_Min, Tbl_Tasks.T102_Mode, Tbl_Tasks.T102_Max),
        Random.Triangular(Tbl_Tasks.T101_Min, Tbl_Tasks.T101_Mode, Tbl_Tasks.T101_Max))
  * Math.If(Prop_Deterministic, 0, 1)
  + Math.If(Prop_Deterministic, <对应 Mean 列>, 0)
```
确定性开关的写法以 #4 实测为准，也可以改成直接切换两套表达式。单位为 Hours。
